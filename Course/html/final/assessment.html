About This Assessment

These questions are different from the ones in each module's knowledge check. Rather than testing recall of a single technique, each question asks you to combine findings across two or more modules — the same way a real examination report does. If a question feels unfamiliar, that is by design: it is testing whether you can apply what you learned to a new scenario, not whether you memorized a specific question.

You may retake this assessment as many times as needed. There is no time limit.

Question 1 of 18
A contract PDF has a /Producer of 'Microsoft Word 2019' in its trailer, but mutool extract reveals an embedded photo with EXIF Make 'Apple' and Model 'iPhone 13'. What is the most defensible interpretation?

Producer describes the application that wrote the PDF container; EXIF Make/Model describes the device that captured an embedded photo. These are independent facts about different objects. They only become suspicious in combination with other evidence (e.g. a claim that all images were scanned, or a GPS location inconsistent with the stated origin).

Question 2 of 18
You find a PDF with 4 %%EOF markers. The Producer in Version 1 is 'LibreOffice 7.0' and the Producer in the final version is 'Adobe Acrobat Reader DC'. What is the most appropriate next investigative step?

A Producer change confirms a different application resaved the file, but it does not by itself tell you what changed. The correct next step is to extract every version, compare content across them, and use annotation timestamps to build a timeline of what was edited and when.

Question 3 of 18
A Form XObject's content stream contains '300 0 0 200 50 700 cm /Im1 Do', and the Form's /BBox is [0 0 150 200]. What fraction of the image is visible?

The cm matrix '300 0 0 200 50 700' scales the image to 300x200pts. The BBox [0 0 150 200] clips anything beyond x=150. Visible width = 150/300 = 50%; height matches (200/200), so 50% of the image area is visible and 50% is clipped by the BBox -- the same BBOX_CROP technique from Module 04, applied to new numbers.

Question 4 of 18
An annotation's /CreationDate is 2025-03-02, the document's /CreationDate is 2025-03-01, and the document's /ModDate is 2025-02-20. Which fact is most significant on its own?

This combines the Module 02 metadata-anomaly concept (impossible date sequences) with Module 03's incremental-update timestamps. ModDate preceding CreationDate is structurally impossible and is the strongest single anomaly here, independent of the annotation timing.

Question 5 of 18
Which single technique would let you confirm whether a 'hidden' image found via a BBOX_CROP finding was also subject to a later incremental update that changed its replacement?

BBOX_CROP (Module 04) and incremental updates (Module 03) are independent techniques that must be combined: extracting prior versions gives you the file as it existed at each save point, and running image extraction against each version separately reveals whether the hidden/cropped image itself changed between versions.

Question 6 of 18
A reviewer annotation has /T '(J. Park)' and a Producer change shows the document was last saved by Adobe Acrobat. What can you conclude about who 'J. Park' is?

The /T field is self-reported by whatever application created the annotation and has no cryptographic verification, as covered in Module 06. The Producer field describes the last save event for the whole document, not necessarily the same session as any specific annotation -- the two facts should not be merged into a single claim.

Question 7 of 18
An image has pixel dimensions 3000x2000 and EXIF GPS coordinates resolving to a location 400 miles from the address on the document. The image is displayed in the PDF at a size implying roughly 72 DPI. List, in order, the three things this combination of facts should make you check.

This draws on Module 04 (DPI/effective-resolution calculation) and Module 06 (GPS/EXIF analysis) together. Each individual fact (GPS mismatch, low DPI) is suggestive on its own; the correct forensic process is to check each independently, then assess whether they corroborate a consistent alternative explanation for the document's origin.

Question 8 of 18
True or false, and why: 'A PDF with only one %%EOF marker has definitely never been edited.'

This is the Module 03 limitations point applied as a general principle: incremental-update analysis is powerful but not exhaustive. Absence of update history is not proof of an unedited document -- it only describes what is preserved in the file you received.

Question 9 of 18
A white-filled rectangle ('1 1 1 rg 100 500 200 20 re f') appears in a content stream immediately after a text block reading '(Total: $4,200) Tj' and immediately before a text block reading '(Total: $6,800) Tj'. What does this sequence describe?

This is the Module 05 white-box overlay pattern: 1 1 1 rg sets fill color to white, the re defines a rectangle over the original text's position, f fills it, and the subsequent Tj draws the replacement value. The original $4,200 is still present in the file -- only the visual rendering is replaced.

Question 10 of 18
Which of these findings, taken alone, would be the WEAKEST evidence of document tampering, and why?

Producer differences between two unrelated documents are expected and meaningless -- different documents are routinely created by different software. The other three options describe internally inconsistent or suspicious patterns within a single document, which is what makes them evidentially meaningful.

Question 11 of 18
You need to verify a finding generated by an automated PDF analysis tool before including it in a report. What is the correct verification approach?

This is the standalone verification principle running through every module: any finding, however generated, should be independently confirmed against the raw object data using manual tools before being relied upon in a report. Re-running the same tool does not constitute independent verification.

Question 12 of 18
A document's XMP stream and Info dictionary disagree: Info shows Producer 'Skia/PDF m124' (Chrome's PDF engine) and XMP shows pdf:Producer 'Microsoft Word 2019'. The document is presented as having been authored in Word. Which source is more likely to reflect what actually happened, and why?

When two metadata sources disagree, prefer the one corroborated by other technical evidence. A specific, recognizable engine signature like Skia/PDF is harder to plausibly explain away than a generic application name, and is consistent with a print-to-PDF workflow rather than direct authorship in Word.

Question 13 of 18
Which combination of techniques would best support a finding that a 'scanned' multi-page document was actually assembled from photographs taken on different days?

No single fact proves 'assembled from photographs on different days' -- it requires combining several Module 06 and Module 04 techniques: different capture dates per image, DPI values inconsistent with scanning, and device fields that may differ page to page if multiple cameras or phones were used.

Question 14 of 18
A page's content stream has two image placements: 'q 200 0 0 150 0 0 cm /ImX Do Q' followed later by 'q 200 0 0 150 0 0 cm /ImY Do Q'. Which image is visible to a viewer, and which is recoverable only by direct extraction?

PDF renders operators in stream order. The second Do call (ImY) paints over the first (ImX) at the identical position, making ImX the OVERLAP back image from Module 04. The q/Q pair only saves/restores graphics state, it does not clip or hide content.

Question 15 of 18
An incremental update's xref table lists only objects 12 and 47 as new/modified, while the document has over 200 objects total. What is the most useful immediate next step?

This is the Module 03 object-level analysis technique: each incremental update's xref table is a precise map of what that save session touched. Two changed objects out of 200+ is not inherently insignificant -- a salary field or a single image swap could live in exactly one or two objects -- but it does tell the examiner exactly where to focus, rather than re-examining the entire file.

Question 16 of 18
An examiner extracts Version 1 of a 3-version PDF and finds the visible salary field reads $85,000. The current (Version 3) file shows $95,000 via an opaque annotation overlay. What is the most precise way to state this finding in a report?

Precise forensic language distinguishes between what the underlying content stream shows, what an overlay displays, and avoids overreaching legal conclusions like 'fraud' -- that determination is outside a technical examiner's scope. The correct report statement describes the technical facts precisely and lets the reader draw conclusions.

Question 17 of 18
Why is it important to hash a file with both MD5 and SHA-256, rather than relying on MD5 alone?

This is the chain-of-custody principle from Module 00, applied with technical reasoning: MD5 is fast and still useful for quick verification, but its known collision weaknesses mean a forensic record should also include a stronger hash like SHA-256.

Question 18 of 18
A document has a single %%EOF, a Producer field consistent with the claimed authoring application, no suspicious annotations, and embedded images with EXIF and DPI values consistent with the claimed capture method. What is the appropriate conclusion?

Forensic findings should be stated in terms of what was and was not found, not overstated as proof of authenticity. A clean result across metadata, structure, overlay, and EXIF checks is meaningful but is not the same as positive proof that no manipulation of any kind occurred.
