Before You Begin

Open a terminal in the folder containing lab04_images.pdf. Also open the file in your PDF viewer so you can compare what the viewer shows against what the tools reveal. You will need a notepad for recording object numbers, BBox values, matrix values, and DPI calculations. Keep the DPI formula handy: effective_dpi = pixel_width × 72 / display_width_pts.

🔬 Page 1 — BBOX_CROP

Page 1 contains a Form XObject whose /BBox is smaller than the image placed inside it. The image extends beyond the BBox in two directions, hiding 75% of its content from any PDF viewer. Your job is to measure the discrepancy and extract the full uncropped image to prove what is hidden.

🪟 Windows
🐧 Linux / macOS
PowerShell — Page 1 BBOX_CROP investigation
# Step 1: Open in peepdf and navigate to page 1 resources
peepdf -i lab04_images.pdf
pdf> tree
# In the output, look for the page 1 entry.
# Under its /Resources you will see /XObject entries.
# One of them will be a Form XObject (Subtype /Form) -- note its object number.

# Step 2: Read the Form XObject dictionary
pdf> object FORM_OBJ_NUM
# Look for and record:
#   /BBox [x1 y1 x2 y2]   <- the visible clipping rectangle
#   The content stream will show a 'cm' matrix and 'Do' call

# Step 3: Decode the Form content stream to see the actual image placement
pdf> stream FORM_OBJ_NUM
# Record the six numbers in the 'cm' matrix: a b c d tx ty
# For a simple scale+translate: 'width 0 0 height 0 0 cm'
# The first value is the image's display width, third is height.

pdf> exit

# Step 4: Extract all images to get the full uncropped pixel data
mutool extract lab04_images.pdf
# This extracts ALL images from ALL pages.
# Identify the page 1 image (largest file is usually it).
Get-FileHash -Algorithm MD5 
# Expected: cf6e8e663cf7ac581fd48f303f15dcb3

# Open the extracted image in an image viewer to see the hidden content:
Invoke-Item
Bash — Page 1 BBOX_CROP investigation
# Step 1: peepdf tree to find Form XObject
peepdf -i lab04_images.pdf
pdf> tree
# Note Form XObject object number under page 1 /Resources

# Step 2: Read the Form dictionary

# Record: /BBox [x1 y1 x2 y2]

# Step 4: Extract images

# Expected page 1 image MD5: cf6e8e663cf7ac581fd48f303f15dcb3

# Open the extracted image:
xdg-open   # or: eog, feh, etc.

  • cm matrix in the Form stream: the image display width and height
  • Crop calculation: visible_width/display_width × visible_height/display_height = visible fraction
  • Hidden fraction = 1 minus visible fraction (answers Q1)

🔬 Page 2 — OVERLAP

Page 2 has two images placed at overlapping positions. The image drawn first in the content stream is completely hidden behind the second. Your task is to identify both images, determine which is on top and which is hidden, and extract the hidden one.

🪟 Windows
🐧 Linux / macOS
PowerShell — Page 2 OVERLAP investigation
# Step 1: Find both image XObject references on page 2
peepdf -i lab04_images.pdf
pdf> page 2
# In the output, look for /XObject entries in the Resources.
# You should see two image names (e.g. /ImB and /ImC) with their object numbers.
# Note both object numbers.

# Step 2: Decode the page 2 content stream to find draw order
pdf> stream PAGE2_CONTENTS_OBJ_NUM
# Look for two 'Do' operators. The one that appears FIRST in the stream
# is drawn FIRST -- it is the back (hidden) image.
# The one that appears SECOND is on top (visible).
# Record which image name (/ImB or /ImC) appears first.
pdf> exit

# Step 3: Extract images from page 2 only
mutool extract -p 2 lab04_images.pdf
# Open both extracted images to see what each contains.
# The hidden (back) image MD5: 4ebd8cefc75e42300bd071f5b86f249f
# The front image MD5:         5f3ce6c1235b1b1ce38a8f356511120b
Bash — Page 2 OVERLAP investigation
# Step 1: Find image XObjects on page 2
peepdf -i lab04_images.pdf
pdf> page 2
# Note both image XObject names and object numbers

# Step 2: Check draw order in content stream
pdf> stream PAGE2_CONTENTS_OBJ_NUM
# First 'Do' = back image (hidden); Second 'Do' = front image (visible)
pdf> exit

# Step 3: Extract page 2 images
mutool extract -p 2 lab04_images.pdf
md5sum img-*.jpg 2>/dev/null
# Back image MD5:  4ebd8cefc75e42300bd071f5b86f249f

🔬 Page 3 — OFFPAGE

Page 3 has an image placed with a negative x coordinate, so part of it lies to the left of the page boundary. The MediaBox left edge is x=0; anything at x<0 is off the visible page. Find the exact placement coordinates from the content stream.

🪟 Windows
🐧 Linux / macOS
PowerShell — Page 3 OFFPAGE investigation
# Step 1: Find page 3 content stream object number
peepdf -i lab04_images.pdf
pdf> page 3
# Note the /Contents object number
pdf> exit

# Step 2: Decode page 3 content stream
qpdf --show-object=PAGE3_CONTENTS_OBJ --filtered-stream-data lab04_images.pdf
# Look for the 'cm' matrix operator.
# The format is: a b c d tx ty cm
# tx is the x position of the image's lower-left corner.
# A negative tx value means the image starts off the left edge of the page.

# Step 3: Find the page MediaBox to calculate the violation magnitude
peepdf -i lab04_images.pdf
pdf> page 3
# Look for /MediaBox [left bottom right top]
# The left edge is the first value (usually 0).
# Violation = |tx| when tx is negative.
pdf> exit
Bash — Page 3 OFFPAGE investigation
peepdf -i lab04_images.pdf
pdf> page 3
# Note /Contents object number and /MediaBox values
pdf> exit

# Decode content stream and find the cm matrix:
qpdf --show-object=PAGE3_CONTENTS_OBJ --filtered-stream-data lab04_images.pdf \
  | grep -E 'cm|Do'
# Look for: NEGATIVE_NUMBER 0 0 HEIGHT 0 0 cm
# The negative first number = off-page displacement
✅
What to record

Write these down in your notes before moving on:

  • cm matrix tx value (the x placement coordinate): is it negative?
  • Page MediaBox left edge: (usually 0)
  • Off-page distance: |tx| points (answers Q3's calculation)
  • Percentage of image width off-page: |tx| / display_width × 100

🔬 Page 4 — DPI_ANOMALY

Page 4 has two images. One has a normal scanner DPI; the other has a suspicious screen-resolution DPI suggesting it is a screenshot rather than a scan. Find each image's pixel dimensions and display size, then calculate effective DPI for each.

🪟 Windows
🐧 Linux / macOS
PowerShell — Page 4 DPI investigation
# Step 1: Find image XObjects on page 4 and get pixel dimensions
peepdf -i lab04_images.pdf
pdf> page 4
# Note image XObject names (e.g. /ImE and /ImF) and object numbers

# Step 2: Read each Image XObject dictionary
pdf> object ImE_OBJ_NUM
# Record: /Width (pixel width), /Height (pixel height)
pdf> object ImF_OBJ_NUM
# Record: /Width, /Height
pdf> exit

# Step 3: Get display sizes from the content stream
# (The cm matrix 'a 0 0 d 0 0 cm' places the image at 'a' pts wide and 'd' pts tall)
qpdf --show-object=PAGE4_CONTENTS_OBJ --filtered-stream-data lab04_images.pdf
# For each image, note the cm matrix before its 'Do' call.

# Step 4: Calculate effective DPI for each image
# Formula: (pixel_width * 72) / display_width_pts
# ImE example: (150 * 72) / 150 = 72 DPI   <- screenshot resolution
# ImF example: (600 * 72) / 144 = 300 DPI  <- scanner resolution
Bash — Page 4 DPI investigation
peepdf -i lab04_images.pdf
pdf> page 4
# Note image object numbers
pdf> object ImE_OBJ_NUM
# Record /Width and /Height
pdf> object ImF_OBJ_NUM
# Record /Width and /Height
pdf> exit

# Get display sizes from content stream:
qpdf --show-object=PAGE4_CONTENTS_OBJ --filtered-stream-data lab04_images.pdf \
  | grep -E 'cm|Do'

# Calculate DPI:
python3 -c "
for name, pw, dw in [('ImE',150,150), ('ImF',600,144)]:
    print(f'{name}: {pw*72/dw:.0f} DPI')
"
✅
What to record

Write these down in your notes before moving on:

  • ImE pixel width × height: _____ × _____
  • ImE display width in pts (from cm matrix): _____
  • ImE effective DPI = pixel_width × 72 / display_pts = _____ (answers Q4)
  • ImF effective DPI: _____ (for comparison)
  • Which DPI is anomalous? (below 100 = screenshot resolution)

📝 Knowledge Check Preparation

Q1: /BBox [0 0 200 150], image placement '400 0 0 300 0 0 cm'. What percentage is hidden?
Visible width = 200/400 = 50%. Visible height = 150/300 = 50%. Visible area = 50% × 50% = 25%. Hidden area = 75%. The image is placed at double the BBox dimensions in both directions, so three-quarters of the pixel data is clipped by the BBox and invisible in any PDF viewer.
Q2: When two images overlap, which is considered the 'back' (hidden) image?
The image drawn first in the content stream. PDF renders content in stream order: later operators paint over earlier ones. The first Do call places the back image; the second Do call places the front image on top of it.
Q3: Image at x=-80 pts on a page with MediaBox [0 0 612 792]. What does OFFPAGE mean?
The image starts 80 points to the left of the visible page edge (x=0). Those 80 points of the image are completely outside the visible area — they are never rendered by any compliant PDF viewer. However, the pixel data for the off-page portion is still fully present in the Image XObject stream in the file.
Q4: Image: 150 pixels wide, displayed at 150 points wide. What is the effective DPI?
(150 × 72) / 150 = 72 DPI. This is screen resolution, consistent with a screenshot taken on a standard-density display. It is inconsistent with a scanned document, which would typically be 200–300 DPI or higher.
Q5: Which command extracts the full uncropped image from a BBOX_CROP finding?
mutool extract lab04_images.pdf — this extracts every Image XObject stream to a file in the current directory, bypassing all display-level clipping including BBox, CropBox, and off-page placement. The extracted file contains the complete pixel data as stored in the PDF, not just the visible portion.
