1️⃣ Step 1 — Install Tools and Configure PATH

Each tool must be added to your system PATH environment variable before it can be run by name from any terminal location. Complete every sub-step below before moving on to Step 2 — Step 3's verification commands will fail otherwise.

🪟 Windows
🐧 Linux / macOS
PowerShell — verify Python and install peepdf
python --version

pip install peepdf-3
peepdf -i  # opens interactive shell -- type 'exit' to leave it

qpdf

Download and run the installer from qpdf.sourceforge.io. By default it installs to a version-specific folder under Program Files. At the time of writing, qpdf 12.3.2 installs to:

qpdf install location (version number will vary)
C:\Program Files\qpdf 12.3.2\bin\

Add that exact \bin folder to your system PATH:

  1. Press the Windows key, type environment variables, and open "Edit the system environment variables"
  2. Click Environment Variables...
  3. Under System variables (or User variables), select Path and click Edit...
  4. Click New and paste the qpdf bin path shown above (adjust the version number to match what you installed)
  5. Click OK on every dialog to save
  6. Open a brand-new terminal window — PATH changes do not apply to terminals already open
PowerShell — verify qpdf is on PATH
qpdf --version

mutool (MuPDF)

⚠️
Prerequisite: Visual Studio

Building mutool from source on Windows requires Visual Studio installed (the free Community edition is sufficient, with the “Desktop development with C++” workload). Install Visual Studio before continuing if you do not already have it.

  1. Download the source release from mupdf.com/releases
  2. Extract the downloaded archive to a convenient location, e.g. C:\Tools\
  3. Navigate to .\mupdf-1.27.2-source\platform\win32\ (the exact folder name depends on the version you downloaded) and double-click mupdf.sln to open it in Visual Studio
  4. In Visual Studio, press Ctrl+Shift+B to build the solution
  5. Once the build completes, the executable will be located at:
mutool build output location (path will vary by version)
.\mupdf-1.27.2-source\platform\win32\x64\Debug\

Add that Debug folder (containing mutool.exe) to your system PATH using the same Environment Variables steps described above for qpdf. Open a new terminal afterward.

PowerShell — verify mutool is on PATH
mutool --version

ExifTool

⚠️
The executable is not named exiftool.exe by default

The file you download from exiftool.org is named exiftool(-k).exe. The (-k) suffix is intentional: it makes double-clicking the file pause and wait for a keypress, which is how the developer designed it for non-technical users testing it via drag-and-drop. For command-line use, you have two options:

  1. Recommended: rename exiftool(-k).exe to exiftool.exe after extracting it. This lets you use the plain command exiftool everywhere in this course exactly as written.
  2. Alternative: leave the filename as-is and type the full name including the parentheses every time, e.g. exiftool(-k).exe lab01_structure.pdf. This is more error-prone and not recommended — every command example in this course uses the plain exiftool name.

After extracting (and optionally renaming) the executable, add the folder containing it to your system PATH using the same Environment Variables steps shown above for qpdf. Open a new terminal afterward.

PowerShell — verify ExifTool is on PATH
exiftool -ver
Bash — install all tools (Debian / Ubuntu / WSL)
python3 --version

pip3 install peepdf-3
sudo apt install qpdf mupdf-tools libimage-exiftool-perl

# Verify all four are installed and on PATH automatically:
qpdf --version && mutool --version && exiftool -ver && peepdf -i

Package manager installs on Linux place each tool's executable directly on PATH automatically — no manual PATH editing is required.

2️⃣ Step 2 — Hash the Lab Files

🪟 Windows
🐧 Linux / macOS
PowerShell — hash all lab files
Get-ChildItem lab0*.pdf | ForEach-Object {
    $md5 = (Get-FileHash $_.Name -Algorithm MD5).Hash
    $sha = (Get-FileHash $_.Name -Algorithm SHA256).Hash
    Write-Host "$($_.Name)";
    Write-Host "  MD5:    $md5"
    Write-Host "  SHA256: $sha"
}
Bash — hash all lab files
for f in lab0*.pdf; do
    echo "$f"
    echo "  MD5:    $(md5sum $f | cut -d' ' -f1)"
    echo "  SHA256: $(sha256sum $f | cut -d' ' -f1)"
done
⚠️
Chain of Custody

In a real investigation, hash the original exhibit before copying it. Record: the tool name and version, the date and time, the file name and path, and both MD5 and SHA-256 values. Notes must be contemporaneous.

3️⃣ Step 3 — Quick Tool Verification

If Step 1 was completed correctly, every command below should run from any folder without errors. If a command is not recognised, double-check that you opened a new terminal window after editing PATH, and that the path you added points to the folder containing the .exe file (not the file itself).

🪟 Windows
🐧 Linux / macOS
Windows — verification commands
# Run against lab01_structure.pdf:

# 1. peepdf
peepdf -i lab01_structure.pdf
# At prompt: objects
# Then: exit

# 2. qpdf structure
qpdf --json lab01_structure.pdf | python -m json.tool | findstr type

# 3. mutool page info
mutool info lab01_structure.pdf

# 4. ExifTool metadata
exiftool lab01_structure.pdf
Linux — verification commands
# Run against lab01_structure.pdf:
peepdf -i lab01_structure.pdf
# At prompt: objects
# Then: exit

qpdf --json lab01_structure.pdf | python3 -m json.tool | grep type
mutool info lab01_structure.pdf
exiftool lab01_structure.pdf
✅
Completion Check

You should see: peepdf shows an object count; qpdf shows JSON structure; mutool shows page dimensions; exiftool shows Creator and Producer fields. All four tools producing output without errors means your environment is ready.
