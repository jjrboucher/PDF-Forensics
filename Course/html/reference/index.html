⚡ Quick Command Reference

Quick Command Reference (all platforms)
# Hash a PDF
md5sum file.pdf                                          # Linux
Get-FileHash -Algorithm MD5 file.pdf                     # Windows

# Count %%EOF markers
grep -c '%%EOF' file.pdf                                  # Linux
python3 -c "d=open('f.pdf','rb').read(); print(d.count(b'%%EOF'))"

# Extract images
mutool extract file.pdf

# Decode a content stream
qpdf --show-object=N --filtered-stream-data file.pdf

# Show a raw object
qpdf --show-object=N file.pdf

# Full JSON structure dump
qpdf --json file.pdf | python3 -m json.tool

# EXIF from extracted image
exiftool image.jpg
exiftool -csv -GPSLatitude# -GPSLongitude# image.jpg

# Launch peepdf in interactive mode:
peepdf -i file.pdf

# peepdf interactive commands:
# pdf> info         -- version, object count, encryption
# pdf> objects      -- list all objects
# pdf> tree         -- document object tree
# pdf> metadata     -- all metadata (Info + XMP)
# pdf> page N       -- inspect page N resources
# pdf> object N     -- inspect object N
# pdf> search /KEY  -- find objects containing /KEY
# pdf> exit

📖 Standards & Specifications

The PDF format and its subsets (PDF/A, PDF/X, PDF/UA, and others) are defined by ISO. The PDF Association maintains the most complete, current cross-reference between ISO document numbers and the PDF nomenclature used in industry — we link to it here rather than reproducing a table that could go stale.

⚠️
Standards Are Not Enforced

None of the ISO PDF standards are mandatory, and there is no conformance authority that tests or certifies PDF-producing software before release. ISO 32000-1 and ISO 32000-2 both explicitly state that they do not specify "methods for validating the conformance of PDF files or PDF processors." In practice, this means any application can write a file that claims to be a PDF while complying with all, some, or almost none of the specification — and most real-world PDF software takes shortcuts somewhere. This is directly relevant to forensic work: a Producer or Creator field that looks unusual, a structure that deviates from the spec, or metadata that seems inconsistent is not automatically evidence of tampering. It may simply reflect how loosely the writing application followed the standard. Treat standards deviation as a data point to investigate, not a finding in itself.
