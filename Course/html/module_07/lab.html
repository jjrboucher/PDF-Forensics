Capstone Lab: Settlement Package SP-2025-0847

Scenario

Document: Settlement Package SP-2025-0847 in the matter of Callahan Property Group v. Meridian Consulting LLC.
Claimed value: $8,500 inflated to $48,500
Claimed creation: Info claims Microsoft Word 2021 (15 October 2025); XMP reveals LibreOffice
Your task: Conduct a complete forensic analysis. There are 5 distinct findings across 5 pages, covering multiple artifact categories.

🚨
Capstone Rules

Work through your own analysis fully before revealing any answers. This exercise tests your ability to conduct an independent examination. The answer key is available at the bottom — use it only to check your findings after you have completed your own work.

⚙️ Your Examination Workflow

This is the capstone: one document, five findings, every technique from Modules 02–06. Work the seven steps in order and record everything — object numbers, commands run, exact values found.

ℹ️
How the expected output works in this lab

Because this is an assessment of your own analysis, the expected output for steps 2–7 is hidden behind a Reveal expected output button under each step. Run the commands and write down what you see first, then reveal to check yourself before moving to the next step.

1
Hash the file

Goal: fix the identity of the evidence before you touch it. Record both hashes, the date and time, and the tool you used. This is the first line of your examination notes.

Windows (PowerShell)
Get-FileHash -Algorithm MD5 lab07_capstone.pdf
Get-FileHash -Algorithm SHA256 lab07_capstone.pdf
Linux / macOS
md5sum lab07_capstone.pdf
sha256sum lab07_capstone.pdf
Terminal — hashing the capstone file
md5sum lab07_capstone.pdf 8f5825be6d70c2f829831e1ad6d904a0 lab07_capstone.pdf sha256sum lab07_capstone.pdf 27d04c06a783b47162cfebc2b719020c8e25ba7deb04be5b4076e261082cac5c lab07_capstone.pdf

👆 Both values must match before you continue. If they do not, re-download the file.

2
Metadata triage (Module 02 technique)

Goal: test the claim on the cover sheet that this package was “prepared in Microsoft Word 2021.” Read the authoring fields from both metadata stores — the Info dictionary and the XMP packet — and compare them. In a genuine file they agree.

The -a -G1 flags make ExifTool show every copy of a tag and label which store it came from ([PDF] = Info dictionary, [XMP-…] = XMP packet):

ExifTool
exiftool -a -G1 -Creator -Producer -CreatorTool -CreateDate -ModifyDate lab07_capstone.pdf

Then confirm the raw values in peepdf:

peepdf session
peepdf -i lab07_capstone.pdf
pdf> metadata
pdf> exit

What to look for: does the Info dictionary’s Creator/Producer match the XMP’s CreatorTool/Producer? Write all four values in your notes before revealing.

Terminal — Info dictionary vs XMP
exiftool -a -G1 -Creator -Producer -CreatorTool ... lab07_capstone.pdf [PDF] Creator : Microsoft Word 2021 [PDF] Producer : Microsoft Word 2021 [XMP-xmp] Creator Tool : LibreOffice Writer 7.6 [XMP-pdf] Producer : LibreOffice 7.6 [PDF] Create Date : 2025:10:15 09:00:00-07:00 [PDF] Modify Date : 2025:11:02 15:00:00-07:00

👆 Finding CAP-01. The Info dictionary (object 2) says Microsoft Word 2021; the XMP packet (object 4) says LibreOffice Writer 7.6. The two stores disagree, so the Word claim does not hold up — one store was edited. Note also the Modify Date of 2 November 2025, 18 days after the stated 15 October date.

3
Incremental update check (Module 03 technique)

Goal: find out whether earlier versions of the document are still inside the file. Count the %%EOF markers: more than one means there are prior revisions to carve out, exactly as you did in Module 03.

Windows (use python3 on Linux / macOS)
python -c "d=open('lab07_capstone.pdf','rb').read(); print(d.count(b'%%EOF'),'EOF markers')"

What to look for: a count of 1 means a single revision; 2 or more means incremental updates.

Terminal — counting %%EOF markers
python -c "d=open('lab07_capstone.pdf','rb').read(); print(d.count(b'%%EOF'),'EOF markers')" 1 EOF markers

👆 One marker — no prior version to recover. This is a result worth recording, not a dead end. A single revision does not mean the file is unaltered: a “Save As” flattens the history. It only means the evidence of tampering has to come from the other techniques in steps 4–6.

4
Text overlay scan — all pages (Module 05 technique)

Goal: check every page for the three overlay techniques: a FreeText annotation covering text, a white rectangle painted in the content stream, and text drawn over text at the same coordinates.

4a — list the annotations. Search for annotation objects, then display each one and read its /Subtype, /Contents and /CreationDate:

peepdf session
peepdf -i lab07_capstone.pdf
pdf> search /Annot
pdf> object {each annotation object number from the search}
pdf> exit

4b — find each page’s content stream. qpdf lists every page with the object number of its content stream:

qpdf
qpdf --show-pages lab07_capstone.pdf

4c — decode each content stream and read it for 1 1 1 rg … re f (a white box) and for two Tj operators at the same Tm position:

qpdf (repeat for each page)
qpdf --show-object={content object number} --filtered-stream-data lab07_capstone.pdf

What to look for: for any overlay, record the covered (original) value, the replacement value, and the object number.

Terminal — annotations
pdf> search /Annot [23, 28] pdf> object 23 << /Type /Annot /Subtype /FreeText /Contents (Payment commencement: 18 July 2025) /Rect [72 664 272 682] /MK << /BG [1 1 1] >> <- opaque white background /CreationDate (D:20251102144500-07'00') /T (M. Reyes) >>

👆 Finding CAP-02. Object 23 is a FreeText annotation on page 2 with a white background, created 2 November 2025. Decoding page 2’s content stream (object 16) shows the text underneath: (Payment commencement: 13 April 2025). Object 28 is a reviewer’s /Text note on page 5 — not an overlay; you will use it in step 6.

Terminal — qpdf --show-pages (content objects)
qpdf --show-pages lab07_capstone.pdf page 1: 13 0 R content: 14 0 R page 2: 15 0 R content: 16 0 R page 3: 17 0 R content: 18 0 R page 4: 19 0 R content: 20 0 R page 5: 21 0 R content: 22 0 R (qpdf also lists any images on each page; omitted here)
Terminal — page 4 content stream (object 20)
qpdf --show-object=20 --filtered-stream-data lab07_capstone.pdf ... heading text ... BT /F1 10 Tf 1 0 0 1 72 660 Tm (Total consideration: $8,500.00) Tj ET <- original 1 1 1 rg 68 656 200 16 re f <- white box painted over it 0 0 0 rg BT /F1 10 Tf 1 0 0 1 72 660 Tm (Total consideration: $48,500.00) Tj ET <- replacement

👆 Finding CAP-04. Page 4 draws the original total, paints a white rectangle over it, then draws a new total on top: $8,500.00 became $48,500.00. Pages 1, 2, 3 and 5 contain no white box and no duplicated text positions.

5
Image manipulation scan — all pages (Module 04 technique)

Goal: check for images that are stored whole but only partly displayed — cropped by a Form /BBox, hidden under another image, or pushed off the page.

5a — look for Form XObjects. Draw the tree and look for an XObject with /Subtype /Form that contains an image. (Forms used only as annotation appearances can be ignored.) Read the form’s /BBox, its drawing stream, and the image’s /Width and /Height:

peepdf + qpdf
peepdf -i lab07_capstone.pdf
pdf> tree
pdf> exit

qpdf --show-object={form object number} --filtered-stream-data lab07_capstone.pdf
qpdf --show-object={image object number} lab07_capstone.pdf

5b — check placement. In the page content streams you decoded in step 4, look at every cm matrix that precedes a Do: a negative x or y means OFFPAGE; two images drawn over the same area means OVERLAP.

5c — extract every image and open each one to see the full stored picture:

mutool
mutool extract lab07_capstone.pdf

What to look for: compare the BBox size with the size the image is drawn at, and calculate the hidden percentage.

Terminal — the Form on page 3 and its image
qpdf --show-object=25 lab07_capstone.pdf (Form XObject used by page 3 as /Fm3) << /Type /XObject /Subtype /Form /BBox [0 0 250 175] <- window: 250 x 175 /Resources << /XObject << /ImR 26 0 R >> >> >> decoded stream: q 500 0 0 350 0 0 cm /ImR Do Q <- image drawn at 500 x 350 qpdf --show-object=26 lab07_capstone.pdf << /Subtype /Image /Width 400 /Height 300 /Filter /DCTDecode ... >>
🧮
Calculate how much is hidden

Visible window = 250×175 = 43,750. Image as drawn = 500×350 = 175,000. Visible = 43,750 / 175,000 = 25%, so 75% of the image is hidden.

Terminal — the extracted image
mutool extract lab07_capstone.pdf extracting image img-0026.jpg extracting image img-0027.jpg # img-0026.jpg, opened in full, also shows the clipped area, which reads: ORIGINAL FEE $8,500 NOT $48,500

👆 Finding CAP-03. Form object 25 clips image object 26; the hidden three-quarters of the image states the original fee was $8,500. (File names follow the object numbers; the extension can vary by mutool version.) No OVERLAP or OFFPAGE placement is present: every other cm has positive coordinates and no page draws two images.

6
EXIF and GPS analysis (Module 06 technique)

Goal: test the claim on page 5 that the photograph was “captured at the Portland signing, 15 October 2025.” Read the EXIF inside the images you extracted in step 5: the device, the capture date, and any GPS position.

ExifTool
exiftool img-*.jpg
exiftool -GPSLatitude# -GPSLongitude# img-*.jpg

What to look for: compare Make/Model, Date/Time Original and GPS against the claimed place and date. Look up any coordinates on a map. Also re-read the reviewer note you found in step 4 (object 28).

Terminal — EXIF of the page 5 photograph
exiftool img-0027.jpg Make : Apple Camera Model Name : iPhone 15 Pro Date/Time Original : 2025:10:28 11:33:12 GPS Latitude : 36 deg 10' 11.64" N GPS Longitude : 115 deg 8' 23.28" W exiftool -GPSLatitude# -GPSLongitude# img-0027.jpg GPS Latitude : 36.1699 GPS Longitude : -115.1398 (img-0026.jpg carries no EXIF device or GPS tags)

👆 Finding CAP-05. 36.1699, −115.1398 is Las Vegas, Nevada, not Portland. The capture date is 28 October 2025 — 13 days after the claimed 15 October signing. The reviewer note in object 28 (/T (M. Patel (QA))) flags the same location problem, which corroborates your result; remember that /T is editable.
