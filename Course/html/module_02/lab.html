Scenario

You have received Meridian Consulting's one-page “Statement of Services” cover memo. Meridian claims it was prepared in Microsoft Word 2019 and finalized on 1 March 2025. Your task is to verify whether the metadata supports or contradicts this claim. There are three planted anomalies in this file; your job is to find and document all three.

ℹ️
Before You Begin

Open a terminal, navigate to the folder containing lab02_metadata.pdf, and prepare a notes document. You will be comparing values across two metadata sources (the Info dictionary and the XMP stream), so a two-column layout works well. Draw a table with columns: Field | Info Dictionary | XMP Stream | Match?

Goal: as with every file, start by confirming your copy is intact. Hash lab02_metadata.pdf and check it against the value in the file panel above.

🔬 Exercise 2 — Extract the Info Dictionary

Goal: read the first of the file’s two metadata stores — the Info dictionary. This is the classic /Creator, /Producer, /CreationDate, /ModDate block. You will read it with two different tools so you can see how each presents the same underlying data; both are standard in casework.

ℹ️
Two metadata stores — this is the whole point of the module

A PDF can carry its metadata in two independent places: the older Info dictionary and the newer XMP packet (Exercise 3). In an untouched file they agree. When they disagree, something edited one and not the other — which is exactly the kind of anomaly this lab is about.

Step 1 — Read the Info dictionary with ExifTool

ExifTool prints metadata with friendly labels, so it is the easiest first look:

🪟 Windows
🐧 Linux / macOS
PowerShell
exiftool lab02_metadata.pdf
Bash
exiftool lab02_metadata.pdf
Terminal — exiftool lab02_metadata.pdf
exiftool lab02_metadata.pdf File Name : lab02_metadata.pdf PDF Version : 1.7 Title : Statement of Services Author : Meridian Consulting Creator : Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/124.0.0.0 Safari/537.36 Producer : Skia/PDF m124 Create Date : 2025:03:01 12:00:00Z Modify Date : 2025:02:15 08:30:00Z ... plus XMP fields, shown in Exercise 3 ...

👆 Two things should already look wrong. The Creator is a Chrome web-browser user-agent string and the Producer is Skia/PDF (the engine Chrome uses to print to PDF) — so this file was printed from a browser, not authored in an office application. And the Modify Date (15 Feb) is earlier than the Create Date (1 Mar), which is impossible. Record all four fields exactly.

Step 2 — Confirm with peepdf (raw values)

ExifTool interprets and relabels fields; peepdf shows you the raw PDF values, which is what you cite in a report. The metadata command prints the Info dictionary (and the XMP packet) together:

peepdf session
peepdf -i lab02_metadata.pdf
pdf> metadata
pdf> exit
Terminal — pdf> metadata (Info dictionary portion)
pdf> metadata Object 2: << /Title Statement of Services /Author Meridian Consulting /Creator Mozilla/5.0 ... Chrome/124.0.0.0 Safari/537.36 /Producer Skia/PDF m124 /CreationDate D:20250301120000+00'00' /ModDate D:20250215083000+00'00' >>

👆 Same values, raw form. The PDF date format is D:YYYYMMDDHHmmSS followed by a UTC offset, so D:20250301120000+00'00' = 1 March 2025, 12:00:00 UTC. Note that D:20250215… (ModDate, 15 Feb) really is before D:20250301… (CreationDate, 1 Mar).

✅
What to record from Exercise 2

From the Info dictionary: Creator = Chrome user-agent, Producer = Skia/PDF m124, CreationDate = 1 Mar 2025, ModDate = 15 Feb 2025. You will put these in the comparison table in Exercise 4.

🔬 Exercise 3 — Extract the XMP Stream

Goal: read the second metadata store — the XMP packet, an XML block embedded as its own object. In an honest file it echoes the Info dictionary. Here you will extract it and discover it tells a different story.

Step 1 — Find the Metadata object

The XMP packet lives in the object referenced by the catalog’s /Metadata key. Find its object number with a search:

peepdf session
peepdf -i lab02_metadata.pdf
pdf> search /Metadata
Terminal — pdf> search /Metadata
pdf> search /Metadata [14]

👆 The search reports that object 14 holds the XMP metadata stream. (Your file uses this number; in general, use whatever the search returns.)

Step 2 — Read the XMP object

Now display that object. Use the number from the previous command:

peepdf session
pdf> object 14   # the metadata object number from the previous command
pdf> exit

You can also pull the decoded XMP straight from the shell with qpdf:

qpdf (decoded XMP)
qpdf --show-object=14 --filtered-stream-data lab02_metadata.pdf
Terminal — the XMP packet (object 14)
qpdf --show-object=14 --filtered-stream-data lab02_metadata.pdf <?xpacket begin="..." ?> <x:xmpmeta ...> <xmp:CreatorTool>Microsoft Word 2019</xmp:CreatorTool> <pdf:Producer>Microsoft Word 2019</pdf:Producer> <xmp:CreateDate>2025-03-01T12:00:00Z</xmp:CreateDate> <xmp:ModifyDate>2025-03-01T12:00:00Z</xmp:ModifyDate> </x:xmpmeta>

👆 Here is the contradiction. The XMP claims the document was created and produced by Microsoft Word 2019 — but the Info dictionary (Exercise 2) said Chrome / Skia. Both cannot be true. One of the two stores was edited to disguise the document’s real origin. Also note the XMP dates agree with each other (both 1 Mar), unlike the impossible Info-dictionary pair.

✅
What to record from Exercise 3

From the XMP: CreatorTool/Producer = Microsoft Word 2019, CreateDate/ModifyDate = 1 Mar 2025. Carry these into the comparison table next.

🔎
The two findings, stated for a report

Finding 1 — Fabricated origin. The Info dictionary identifies the producing software as Chrome/Skia (a browser “print to PDF”), while the XMP packet claims Microsoft Word 2019. Because a genuine file’s two metadata stores agree, this mismatch indicates the metadata was altered to disguise how the document was really made.

Finding 2 — Impossible timeline. The Info dictionary’s ModDate (15 Feb 2025) precedes its CreationDate (1 Mar 2025). A document cannot be modified before it exists, so at least one of these timestamps was edited.

ℹ️
How to spot the anomalies

ANOMALY-1 (Origin mismatch): Does the Creator string match what you would expect from Microsoft Word? A Creator string starting with Mozilla/5.0 is a browser user-agent — the document was printed to PDF in Chrome, not authored in Word.

ANOMALY-2 (Impossible date): Compare the CreationDate and ModDate. Can a document be modified before it was created? If ModDate is earlier than CreationDate, one of those values has been manually edited.

ANOMALY-3 (Info/XMP divergence): Do the values in both columns match? A mismatch means one source was edited after the other was written. The unedited source holds the original value.

📝 Knowledge Check Preparation

Use your notes to answer these questions before checking the answers below.

Q1: The /Creator field contains a Chrome user-agent string. What does this tell you about the document's origin?

It was printed from a web browser, not authored in office software.

The /Creator field is supposed to name the application that created the source document. A value like Mozilla/5.0 (Windows NT 10.0; Win64; x64) … Chrome/124.0.0.0 Safari/537.36 is a browser user-agent string — it is what Google Chrome writes when you use its built-in “Print → Save as PDF.” Paired with the /Producer value Skia/PDF m124 (Skia is Chrome’s graphics/PDF engine), this is an unambiguous fingerprint of a Chrome print-to-PDF.

Why it matters: a document presented as an official Word-authored record but actually generated by printing a web page from a browser did not originate the way its author claims. On its own that is a strong lead; combined with the conflicting XMP (Q3) it becomes a finding.

Q2: The ModDate is 15 February 2025 but the CreationDate is 1 March 2025. What is the correct conclusion?

At least one timestamp was altered — the timeline is impossible.

A document cannot be modified before it is created. Here the Info dictionary says it was last modified on 15 Feb 2025 but first created on 1 Mar 2025 — the modify date is two weeks earlier than the create date. That ordering is structurally impossible in a genuine file, so one of the two dates was edited by hand.

How to state it: “The Info dictionary’s ModDate (D:20250215083000) precedes its CreationDate (D:20250301120000). As a document cannot be modified before creation, at least one timestamp has been manually altered.” Always quote the raw D: values in the report, not just the friendly dates.

Q3: Which source (Info dict or XMP) more likely reflects the true Creator/Producer?

The Info dictionary — it is internally consistent with how the file was actually produced.

The Info dictionary’s Creator (Chrome user-agent) and Producer (Skia/PDF) agree with each other and both point to the same thing: a browser print-to-PDF. The XMP, by contrast, claims Microsoft Word 2019 for both fields — a tidy, generic value with no corroboration anywhere else in the file. When one story is supported by multiple independent details and the other is a lone round claim, the corroborated one is more credible.

Caveat worth stating: metadata of either kind is editable, so you present this as the more likely true origin based on internal consistency, not as proof. The defensible conclusion is that the two stores disagree and were therefore tampered with — which is itself the finding, regardless of which one is “true.”

Q5: What peepdf command displays all metadata fields from both the Info dictionary and XMP stream?

metadata — run it after opening the file:

peepdf -i lab02_metadata.pdf
pdf> metadata

It prints the Info dictionary and the XMP packet together in one view, which makes it the fastest way to eyeball both metadata stores at once and spot a disagreement. For a careful report you then read each store on its own — the Info dictionary via metadata or ExifTool, and the raw XMP via object {metadata object number} or qpdf --show-object=N --filtered-stream-data — so you can quote exact values.

Documentation Exercise

Write two sentences suitable for inclusion in a forensic report about ANOMALY-2 (the impossible date). Your statement must: (1) state both date values precisely; (2) explain why the sequence is impossible; (3) state the forensic conclusion. Write your answer before revealing the model below.

Model statement: “The Info dictionary records a ModDate of 15 February 2025 (D:20250215083000+00'00'), which precedes the document CreationDate of 1 March 2025 (D:20250301120000+00'00') by 14 days. As a document cannot be modified before it is created, this sequence is structurally impossible in a legitimately produced PDF file and is consistent with the deliberate manual editing of one or both date fields after the document was originally produced.”
