Before You Begin

Open a terminal in the folder containing lab05_textoverlay.pdf and also open the file in your PDF viewer. For each page, look at what the viewer displays, then run the commands to find what is actually in the file structure. Keep notes recording: the overlay type, the original value, the replacement value, the object number, and the detection method used.

🔬 Page 1 — Annotation Overlay

ℹ️
What this module is about

Changing a number in a PDF without re-typesetting the page is usually done by covering the old value and drawing a new one on top. Three ways to do it: a FreeText annotation with an opaque background, a white rectangle painted in the content stream, or drawing new text directly over old text. In all three the original value is still in the file — and because the covering is a visual trick, pdftotext and a decoded content stream recover the original underneath. Each page below is one technique.

The technique: a /FreeText annotation with an opaque white background is dropped over the original date. The annotation sits above the page content, so it hides the old date and shows a new one. But an annotation is a separate object with its own /CreationDate — so it also timestamps the edit, and the original date is untouched in the page content underneath.

Step 1 — Find the annotation

peepdf session
peepdf -i lab05_textoverlay.pdf
pdf> search /Annot
Terminal — pdf> search /Annot
pdf> search /Annot [19]

👆 One annotation: object 19.

Step 2 — Read the annotation’s fields

peepdf session
pdf> object 19
pdf> exit
Terminal — the overlay annotation
pdf> object 19 << /Type /Annot /Subtype /FreeText /Contents (Date: Wednesday, 19 March 2025) <- the replacement /Rect [68 648 320 668] /MK << /BG [1 1 1] >> <- opaque WHITE background (hides what is under it) /CreationDate (D:20250320091500-07'00') <- when the overlay was added >>

👆 The annotation pastes “Date: Wednesday, 19 March 2025” on a white background, and its /CreationDate is 20 March 2025.

Step 3 — Recover the original date (underneath)

The annotation only covers the page; the original date is still in the page’s own text. Extract the page text to read both:

extract page text
pdftotext -layout lab05_textoverlay.pdf -
Terminal — original and overlay both present
pdftotext -layout lab05_textoverlay.pdf - Date: Saturday, 15 March 2025 <- original, in the page content Date: Wednesday, 19 March 2025 <- overlay, from the annotation

👆 The original date was Saturday, 15 March 2025; the overlay changed it to Wednesday, 19 March 2025. And the annotation’s CreationDate (20 March) is after the document’s own date — proof the overlay was added later.

✅
What to record

FreeText annotation (obj 19) with opaque white /BG overlays the date; /CreationDate dates the edit (20 Mar 2025). Original date (15 Mar 2025) recovered from the page text underneath. Finding class: annotation overlay.

🔬 Page 2 — White-Box Overlay

The technique: the editor paints a filled white rectangle over the original total directly in the page’s content stream, then draws the new total on top. There is no annotation this time — the cover-up is baked into the page. But the original Tj (show-text) operator is still in the stream, before the white box, so it extracts normally.

Step 1 — Decode the page-2 content stream

decode page 2 content
qpdf --show-object=16 --filtered-stream-data lab05_textoverlay.pdf
Terminal — the white-box cover-up in the content stream
qpdf --show-object=16 --filtered-stream-data lab05_textoverlay.pdf ... page heading text ... BT /F1 11 Tf 1 0 0 1 72 630 Tm (Total: $8,500.00) Tj ET <- original 1 1 1 rg 68 626 120 16 re f <- paint a WHITE box over it 0 0 0 rg BT /F1 11 Tf 1 0 0 1 72 630 Tm (Total: $48,500.00) Tj ET <- new total on top
🔎
Read the three operators

1 1 1 rg sets the fill colour to white (R=1, G=1, B=1). 68 626 120 16 re defines a rectangle at (68, 626), 120 wide, 16 tall — positioned exactly over the original total. f fills it. The sequence “draw text → paint a white box over it → draw new text” is the white-box overlay signature.

Step 2 — Recover the original total

Because the original Tj is still in the stream, plain text extraction returns both values:

extract page text
pdftotext -layout lab05_textoverlay.pdf -
Terminal — both totals present
pdftotext -layout lab05_textoverlay.pdf - Total: $8,500.00 <- original (under the white box) Total: $48,500.00 <- the overlay

👆 The original total was $8,500.00; the white box hid it and $48,500.00 was drawn on top — a $40,000 inflation hidden behind a white rectangle.

✅
What to record

Content stream (obj 16) paints a white rectangle (1 1 1 rg 68 626 120 16 re f) over the original Total: $8,500.00 and draws $48,500.00 on top. Original recovered via pdftotext. Finding class: white-box overlay.

🔬 Page 3 — Text-Over-Text Overlay

The technique: the subtlest of the three. No white box, no annotation — the editor simply draws the replacement text at the exact same coordinates as the original, so the new characters land directly on top of the old ones. Visually the old text is hidden by the new; in the content stream there are simply two Tj operations at the same position.

Step 1 — Decode the page-3 content stream

decode page 3 content
qpdf --show-object=18 --filtered-stream-data lab05_textoverlay.pdf
Terminal — two text draws at one position
qpdf --show-object=18 --filtered-stream-data lab05_textoverlay.pdf ... page heading text ... BT /F1 11 Tf 1 0 0 1 155 656 Tm (Sat) Tj ET <- original, at (155, 656) BT /F1 11 Tf 1 0 0 1 155 656 Tm (Wed) Tj ET <- replacement, SAME (155, 656)

👆 Two text objects draw at the identical position 1 0 0 1 155 656 Tm: first “Sat”, then “Wed” on top of it. Two Tj at the same Tm coordinates is the text-over-text signature.

Step 2 — Recover the original word

extract page text
pdftotext lab05_textoverlay.pdf -
Terminal — both words extracted
pdftotext lab05_textoverlay.pdf - ... on page 3 the extracted text contains both: Sat (original) Wed (overlay)
🔎
Why this is the hardest to spot — and how to catch it

There is no white box or annotation to flag, and on screen the two words sit perfectly on top of each other, so nothing looks wrong. The tell is only in the content stream: two show-text operators at identical coordinates. Scan decoded streams for repeated Tm positions, and compare extracted text against what the page visually shows — an extra word that is not visible is the giveaway.

✅
What to record

Content stream (obj 18) draws “Sat” then “Wed” at the same coordinates (155, 656). Original recovered from the stream / text extraction. Finding class: text-over-text overlay (the hardest to detect visually).

📝 Knowledge Check Preparation

Q1: A FreeText annotation has /MK << /BG [1 1 1] >>. What does this indicate?

The annotation has an opaque white background, so it is covering up whatever is on the page beneath it.

/MK << /BG [1 1 1] >> is the annotation’s appearance characteristics (/MK) with a background colour (/BG) of [1 1 1] — pure white in RGB. A FreeText annotation with an opaque white background is the classic “sticker over the original” edit: the white fill hides the page content underneath, and the annotation’s /Contents shows the replacement text.

What to do with it: read the annotation’s /CreationDate to date the edit, then extract the page text (pdftotext) to recover the original value the annotation is hiding — here, the original date of 15 March 2025.

Q2: In a decoded content stream: '1 1 1 rg 68 626 120 16 re f'. What is this doing?

It paints a solid white rectangle over a region of the page — a white-box cover-up.

Read the three operators in order:

  • 1 1 1 rg — set the fill colour to white (R=1, G=1, B=1).
  • 68 626 120 16 re — define a rectangle at (68, 626), 120 points wide and 16 tall.
  • f — fill that rectangle with the current colour (white).

Positioned exactly over the original total and followed by a new Tj drawing $48,500.00, this hides the real value behind a white box and prints the inflated one on top. Because the original Tj is still in the stream, pdftotext recovers the hidden $8,500.00.

Q3: What makes text-over-text overlay the hardest technique to detect?

There is nothing visual to flag — no annotation and no white box — because the replacement is drawn at the exact same coordinates as the original, directly on top of it.

The annotation and white-box techniques both leave an obvious artefact (an extra object, or a filled rectangle). Text-over-text leaves neither: the content stream simply contains two Tj show-text operations at the identical Tm position, so on screen the new word sits perfectly over the old one and the page looks completely normal.

How you catch it anyway: it only shows up in the decoded content stream, as two text draws at the same coordinates, and in text extraction, as an extra word that is not visible on the page. The habit of comparing extracted text against what the page actually displays is what exposes it — here, “Sat” drawn under “Wed” at (155, 656).

Q4: Annotation CreationDate is 20 March 2025; document /CreationDate is 10 March 2025. What is the significance?

The overlay was added ten days after the document was created — so it is a later modification, not part of the original document.

The document’s own /CreationDate (10 March 2025) is when the file was made. The annotation’s /CreationDate (20 March 2025) is when that sticky-note overlay was placed. An annotation dated after the document it sits on could not have been part of the original — it was added during a later editing session. That timestamp converts “there is an overlay” into “the overlay was applied on 20 March, ten days after creation,” which is a far stronger statement for a report.

Caveat: both dates are editable metadata, so corroborate the timeline where you can (incremental-update history, other timestamps). But a creation-date ordering that is internally impossible-to-explain — an overlay predating nothing, added after the fact — is solid supporting evidence of post-creation tampering.
