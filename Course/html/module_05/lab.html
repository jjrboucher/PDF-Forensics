Lab: Three Pages, Three Overlay Techniques

Each page uses a different method to display replacement text over original content. Work each page carefully — the detection method is different for each one.

Before You Begin

Open a terminal in the folder containing lab05_textoverlay.pdf and also open the file in your PDF viewer. For each page, look at what the viewer displays, then run the commands to find what is actually in the file structure. Keep notes recording: the overlay type, the original value, the replacement value, the object number, and the detection method used.

🔬 Page 1 — Annotation Overlay

Page 1 has a FreeText annotation placed over the invoice date. The annotation has an opaque white background that covers the original date, and displays a replacement date instead. Find the annotation object, read its fields, and establish whether it was added after the document was created.

🪟 Windows
🐧 Linux / macOS
PowerShell — Page 1 annotation investigation
# Step 1: Check what annotations exist on page 1
peepdf -i lab05_textoverlay.pdf
pdf> page 1
# Look for /Annots in the page dictionary output.
# It will list annotation object numbers (e.g. [7 0 R])
# Note each annotation object number.

# Step 2: Read the annotation object
pdf> object 7
# (Replace 7 with the actual annotation object number)
# In the output, look for and record ALL of these:
#   /Subtype    <- should be /FreeText
#   /Rect       <- [x1 y1 x2 y2] position on page
#   /Contents   <- the REPLACEMENT text the annotation displays
#   /MK /BG     <- background colour; [1 1 1] = opaque white (covers original)
#   /DA         <- default appearance (font and colour)
#   /CreationDate <- when the annotation was added
pdf> exit

# Step 3: Compare annotation CreationDate to document CreationDate
peepdf -i lab05_textoverlay.pdf
pdf> metadata
# Record the document /CreationDate
# Is the annotation CreationDate LATER than the document CreationDate?
# If yes: the annotation was added AFTER the document was created.
pdf> exit

# Step 4: Verify with qpdf (independent confirmation)
qpdf --show-object=7 lab05_textoverlay.pdf

🔬 Page 2 — White-Box Overlay

Page 2 uses a different technique: a white-filled rectangle drawn directly in the page content stream covers the original invoice total, and replacement text is drawn on top. There is no annotation object for this one — you find it only by decoding the content stream and looking for the specific operator sequence.

🪟 Windows
🐧 Linux / macOS
PowerShell — Page 2 white-box investigation
# Step 1: Find the page 2 content stream object number
peepdf -i lab05_textoverlay.pdf
pdf> page 2
# Look for /Contents N 0 R in the output
# Record the object number N
pdf> exit

# Step 2: Decode the content stream
qpdf --show-object=PAGE2_CONTENTS_OBJ --filtered-stream-data lab05_textoverlay.pdf > page2_stream.txt
notepad page2_stream.txt

# Step 3: In the file, search for this three-operator sequence:
# 1 1 1 rg     <- set fill colour to WHITE (RGB 1,1,1)
# X Y W H re   <- define rectangle at position (X,Y) with width W and height H
# f            <- FILL the rectangle with the current colour (white)
# The text immediately before this sequence is the ORIGINAL text.
# The text immediately after is the REPLACEMENT text.
# Record: the rectangle coordinates, the original text, and the replacement text.
Bash — Page 2 white-box investigation
# Step 1: Find page 2 content stream object number
peepdf -i lab05_textoverlay.pdf
pdf> page 2
# Note /Contents object number
pdf> exit

# Step 2: Decode and search for white-box sequence
qpdf --show-object=PAGE2_CONTENTS_OBJ --filtered-stream-data lab05_textoverlay.pdf \
  | grep -n -B5 -A5 '1 1 1 rg'

# The -B5 shows 5 lines before (original text)
# The -A5 shows 5 lines after (rectangle definition and fill)
# Look for: 1 1 1 rg -> X Y W H re -> f -> BT...(replacement)...ET

🔬 Page 3 — Text-Over-Text Overlay

Page 3 uses the hardest technique to detect: replacement text drawn at exactly the same coordinates as the original text. There is no annotation, no white rectangle — only careful reading of the decoded content stream reveals it. You are looking for two BT...ET blocks that position text at the same coordinates.

🪟 Windows
🐧 Linux / macOS
PowerShell — Page 3 text-over-text investigation
# Step 1: Find the page 3 content stream
peepdf -i lab05_textoverlay.pdf
pdf> page 3
# Note /Contents object number
pdf> exit

# Step 2: Decode and save the content stream
qpdf --show-object=PAGE3_CONTENTS_OBJ --filtered-stream-data lab05_textoverlay.pdf > page3_stream.txt
notepad page3_stream.txt

# Step 3: Read through the decoded stream.
# Look for ALL text operators (Td, Tj, TJ) and their coordinates.
# The key indicator: two BT...ET blocks where the 'Td' operator
# specifies the SAME x,y coordinates but DIFFERENT text in the 'Tj' call.
# Example of what to look for:
#   BT  155 656 Td  (Sat) Tj  ET   <- original (drawn first)
#   BT  155 656 Td  (Wed) Tj  ET   <- replacement (same position, different text)
# Record: the coordinates, the first (original) text, the second (replacement) text.
Bash — Page 3 text-over-text investigation
# Find page 3 content stream:
peepdf -i lab05_textoverlay.pdf
pdf> page 3
# Note /Contents object number
pdf> exit

# Decode and extract all text operator lines:
qpdf --show-object=PAGE3_CONTENTS_OBJ --filtered-stream-data lab05_textoverlay.pdf \
  | grep -n 'Td\|Tj\|BT\|ET'

# Look for the SAME Td coordinate appearing twice with different Tj content.
# The first occurrence is the original; the second is the replacement.
✅
What to record

Write these down in your notes before moving on:

  • Coordinate pair (from Td operator): (x, y) where the overlap occurs
  • Original word: the text string in the first Tj at those coordinates
  • Replacement word: the text string in the second Tj at those coordinates (answers Q3)
  • Why this is hard to detect: no /Annots entry, no white rectangle — only visible when you decode the content stream and compare Td positions

📝 Knowledge Check Preparation

Q1: A FreeText annotation has /MK << /BG [1 1 1] >>. What does this indicate?
/BG sets the annotation background colour using RGB values from 0 to 1. [1 1 1] is white. An opaque white background means the annotation visually covers any content beneath it — the original text cannot be seen through the annotation. This is the defining characteristic of an annotation-based overlay.
Q2: In a decoded content stream: '1 1 1 rg 68 630 120 16 re f'. What is this doing?
'1 1 1 rg' sets the fill colour to white (RGB 1,1,1). '68 630 120 16 re' defines a rectangle at x=68, y=630, width=120, height=16. 'f' fills that rectangle with the current colour (white). The result: a white-filled rectangle 120×16 points at position (68,630) that covers any text in that area.
Q3: What makes text-over-text overlay the hardest technique to detect?
There is no annotation in the /Annots array (nothing visible in an annotation panel), no white rectangle in the content stream, and the replacement character paints over the original at the same coordinates — a PDF viewer shows only the final rendered result. Detection requires decoding the content stream and finding two BT...ET blocks with overlapping Td coordinate positions.
Q4: Annotation CreationDate is 20 March 2025; document /CreationDate is 10 March 2025. What is the significance?
The annotation was created 10 days after the document was originally produced. An annotation /CreationDate that is later than the document /CreationDate is evidence that the document was modified after it was first created — the annotation was added as a post-creation edit. Combined with an opaque white background and a /Contents that differs from the underlying text, this constitutes evidence of deliberate text replacement.
