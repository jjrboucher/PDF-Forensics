PDF Internals — Knowledge Check

6 questions covering file structure, objects, streams, and XObjects.

📋
Knowledge Check
Answer all questions — 70% required to mark module complete
Question 1 of 6
Which section of a PDF file contains a lookup table mapping object numbers to byte offsets?

The cross-reference table (xref) maps each object number to its byte offset in the file. This enables random access — a reader can jump directly to any object without reading the whole file.

Question 2 of 6
A page's visible content (text, graphics, image placements) is stored in which object?

The page's /Contents key references a stream object containing the page's content stream — a sequence of graphics operators encoding all visible content.

Question 3 of 6
What is the forensic significance of the /BBox entry in a Form XObject?

The /BBox defines the region of the Form XObject that is rendered. Any image placed inside the Form that extends beyond /BBox is clipped — its pixel data remains in the file but is invisible. This is the BBOX_CROP artifact.

Question 4 of 6
Which PDF graphics operator places an XObject (image or form) onto the page?

The 'Do' operator invokes a named XObject from the page's resource dictionary. Every image placement in a PDF is ultimately made through a 'Do' call.

Question 5 of 6
A content stream uses /Filter /FlateDecode. What does this mean?

/FlateDecode indicates the stream data is compressed using zlib/DEFLATE. To read the raw operators you must decompress the stream first — which qpdf does with --filtered-stream-data.

Question 6 of 6
When you run 'mutool extract lab01_structure.pdf', what does it produce?

'mutool extract' extracts all embedded image and font resources to files in the current directory. For forensic purposes this gives you the full, uncropped image data regardless of how it is displayed in the PDF.
