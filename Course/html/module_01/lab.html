Before You Begin

Open a terminal and navigate to the folder containing lab01_structure.pdf. Keep a notepad document or paper beside you and write down the answers as you discover them — each exercise builds on the one before it. This is a clean file with no manipulation artifacts; the goal here is to become comfortable navigating the structure of a normal PDF before you encounter manipulated ones in later modules.

🔬 Exercise 1 — Verify the File

Before examining any file, always hash it and confirm it matches the expected value. This establishes that your copy is intact and gives you a defensible record if the file is ever questioned. Run the command below and compare the output to the MD5 shown in the file panel above.

🪟 Windows
🐧 Linux / macOS
PowerShell — hash the file
Get-FileHash -Algorithm MD5 lab01_structure.pdf
# Expected: 5440841e16b52738b7bdc352fda1bb1e

# If the hashes match, your copy is intact. Record the result in your notes.
Bash — hash the file
md5sum lab01_structure.pdf
# Expected: 5440841e16b52738b7bdc352fda1bb1e

# If the hashes match, your copy is intact. Record the result in your notes.

What to record

🔬 Exercise 2 — Inspect the File with peepdf

Launch peepdf in interactive mode and run four commands in sequence. Each one reveals a different layer of the file structure. Read the output carefully after each command before moving to the next — you are looking for specific values that answer the questions below.

🪟 Windows
🐧 Linux / macOS
PowerShell — peepdf interactive session
peepdf -i lab01_structure.pdf

# Command 1: file summary
pdf> info
# Look for: PDF version, number of objects, encryption status
# Record: the version string and object count

# Command 2: list all objects
pdf> objects
# Look for: each object number and its type (/Catalog, /Pages, /Page, /XObject, etc.)
# Record: the object numbers for the Catalog, the Pages tree, and any Image objects

# Command 3: show the document hierarchy
pdf> tree
# Look for: the chain Catalog -> Pages -> Page -> Contents/Resources
# Record: which object numbers appear at each level

# Command 4: display all metadata
pdf> metadata
# Look for: Creator, Producer, CreationDate, ModDate
# Record: all four values exactly as shown

pdf> exit
Bash — peepdf interactive session

🔬 Exercise 3 — Read a Specific Object

From Exercise 2 you noted the object number of the first /Page dictionary. Now retrieve that object directly and read its keys. This is the same command you will use in every later module to independently verify any finding the forensics application reports: look up the object number from the report, run this command, read the raw data.

🪟 Windows
🐧 Linux / macOS
PowerShell — inspect the Page object
# Replace PAGE_OBJ_NUM with the object number you recorded in Exercise 2
# (the number next to /Page in the objects list)

# Method A: in peepdf
peepdf -i lab01_structure.pdf
pdf> object PAGE_OBJ_NUM
pdf> exit

# Method B: with qpdf (no interactive session needed)
qpdf --show-object=PAGE_OBJ_NUM lab01_structure.pdf

# Look for these keys in the output:
# /Type /Page          <- confirms this is a page object
# /MediaBox [...]      <- the page dimensions in points
# /Contents N 0 R      <- object number of the content stream (record this)
# /Resources N 0 R     <- object number of the resources dictionary (record this)
Bash — inspect the Page object
# Replace PAGE_OBJ_NUM with the number from Exercise 2

# Method A: in peepdf
peepdf -i lab01_structure.pdf
pdf> object PAGE_OBJ_NUM
pdf> exit

# Method B: with qpdf
qpdf --show-object=PAGE_OBJ_NUM lab01_structure.pdf

# Look for:
# /Type /Page
# /MediaBox [...]      <- page dimensions
# /Contents N 0 R      <- record this object number
# /Resources N 0 R     <- record this object number
✅
What to record from Exercise 3

☐ For Exercise 4: note the object number next to /Contents in the Page dictionary output. This is the content stream you will decode in the next step.
☐ For Exercise 4: also note the object number next to /Resources — this is where the image XObject reference lives.

🔬 Exercise 4 — Decode the Content Stream

The /Contents object you identified in Exercise 3 holds the page drawing instructions in a FlateDecode-compressed stream. Use qpdf to decompress and print it. This is how you will examine content streams in every subsequent module when looking for text overlay operators (1 1 1 rg re f), image placement (cm Do), and text blocks (BT ... ET).

🪟 Windows
🐧 Linux / macOS
PowerShell — decode the content stream
# Replace CONTENTS_OBJ_NUM with the /Contents object number from Exercise 3

qpdf --show-object=CONTENTS_OBJ_NUM --filtered-stream-data lab01_structure.pdf

# The output will be the raw PDF drawing operators. Look for:
# BT ... ET           <- text block (everything between is a text drawing instruction)
# /F1 12 Tf           <- set font F1 at 12 points
# 72 700 Td           <- move text cursor to position (72, 700)
# (some text) Tj      <- render the string
# q ... cm ... Do Q   <- image placement block

# Redirect to a file for easier reading:
qpdf --show-object=CONTENTS_OBJ_NUM --filtered-stream-data lab01_structure.pdf > stream_decoded.txt
notepad stream_decoded.txt
Bash — decode the content stream
# Replace CONTENTS_OBJ_NUM with the /Contents object number from Exercise 3

qpdf --show-object=CONTENTS_OBJ_NUM --filtered-stream-data lab01_structure.pdf

# Look for:
# BT ... ET           <- text block
# q ... cm ... Do Q   <- image placement

# Filter for just the key operators:
qpdf --show-object=CONTENTS_OBJ_NUM --filtered-stream-data lab01_structure.pdf \
  | grep -E '(BT|ET|^q$|^Q$|cm|Do)'

# Save to file for easier reading:
qpdf --show-object=CONTENTS_OBJ_NUM --filtered-stream-data lab01_structure.pdf > stream_decoded.txt
cat stream_decoded.txt
✅
What to record from Exercise 4

☐ For Exercise 5: in the image placement block (q ... cm ... Do Q), note the name of the XObject being invoked (e.g. /Im0). Then look up that name in the /Resources dictionary (use qpdf --show-object=RESOURCES_OBJ_NUM lab01_structure.pdf or pdf> object RESOURCES_OBJ_NUM in peepdf) to find the Image XObject's object number.

☐ Q3 answer: once you have the Image XObject object number, run qpdf --show-object=IMAGE_OBJ_NUM lab01_structure.pdf and read the /Filter value.

🔬 Exercise 5 — Extract the Embedded Image

mutool extracts every embedded image from a PDF to individual files in the current directory. This bypasses all display-level clipping (BBox, CropBox, off-page placement) and gives you the raw pixel data exactly as stored in the file. In later modules this is how you will reveal content that is invisible in a PDF viewer.

🪟 Windows
🐧 Linux / macOS
PowerShell — extract and verify the image
# Extract all embedded images:
mutool extract lab01_structure.pdf

# mutool will report the filenames it created (e.g. img-0001.jpg)
# List what was extracted:
Get-ChildItem img-*.jpg

# Hash the extracted image and compare to the expected value:
Get-FileHash -Algorithm MD5 img-*.jpg
# Expected MD5: a61237da1ef601b7019bc2218871cbb5

# Open the image to see its contents:
Invoke-Item img-*.jpg
Bash — extract and verify the image
# Extract all embedded images:
mutool extract lab01_structure.pdf

# List what was extracted:
ls -lh img-*.jpg

# Hash and compare:
md5sum img-*.jpg
# Expected MD5: a61237da1ef601b7019bc2218871cbb5

# Open the image:
xdg-open img-*.jpg   # Linux
open img-*.jpg       # macOS
✅
What to record from Exercise 5

☐ Q4 answer: the MD5 of the extracted image file. It should match a61237da1ef601b7019bc2218871cbb5. If it does not, re-download the lab file and repeat from Exercise 1.

📝 Model Answers

Try each question from your own notes first, then reveal to check.

Q1: Does the file MD5 match the expected value?
Yes — the expected MD5 is 5440841e16b52738b7bdc352fda1bb1e. If yours does not match, re-download the lab file from the panel above.
Q2: What PDF version is declared in the header, and how many objects does the file contain?
Run pdf> info in peepdf. The header declares PDF 1.7 (%PDF-1.7). The object count is shown as Objects in the info output. Record the exact number you see — it will match the number of entries in the xref table minus the one free-object entry (entry 0 65535 f).
Q3: What is the /Filter on the image stream, and what does it mean?
/DCTDecode — this is JPEG compression. You can confirm this by running qpdf --show-object=IMAGE_OBJ_NUM lab01_structure.pdf and reading the /Filter key. DCTDecode is the most common filter for photographic colour images in PDF.
Q4: What is the MD5 of the extracted image file?
a61237da1ef601b7019bc2218871cbb5 — produced by mutool extract and verified with Get-FileHash / md5sum. This hash identifies the exact pixel data stored in the PDF, independent of how it is displayed.
Q5: How many pages does the /Pages object's /Count entry declare?
2 — visible in the pdf> tree output or by running qpdf --show-object=PAGES_OBJ_NUM lab01_structure.pdf and reading /Count 2.
