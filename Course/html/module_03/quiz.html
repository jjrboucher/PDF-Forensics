Incremental Updates — Knowledge Check

📋
Knowledge Check
Answer all questions — 70% required to mark module complete
Question 1 of 5
A PDF file contains 3 %%EOF markers. How many incremental updates does this indicate?

Number of incremental updates = number of %%EOF markers minus 1. Three %%EOF markers = 2 incremental updates (the original creation plus 2 subsequent saves).

Question 2 of 5
When extracting Version 1 from a 3-version PDF, what bytes do you copy?

Version 1 consists of all bytes from offset 0 through the first %%EOF marker (inclusive). In Python: d[:first_eof_offset + 5], where +5 includes the 5-byte %%EOF string.

Question 3 of 5
The /Prev entry in an incremental update trailer serves what purpose?

The /Prev entry contains the byte offset of the xref table from the previous version. This chain of /Prev pointers allows navigation backwards through all versions of the document.

Question 4 of 5
Version 1 Producer is 'Microsoft Word 2019' and Version 2 Producer is 'Adobe Acrobat Reader DC 23.0'. What does this indicate?

The Producer field identifies the application that wrote each version. Version 1 (Word) is the original creation. Version 2 (Acrobat Reader) means the file was subsequently opened and saved in Acrobat Reader — the typical Fill & Sign workflow.

Question 5 of 5
A document is described as 'linearised'. How does this affect %%EOF count analysis?

Linearised (web-optimised) PDFs contain 2 %%EOF markers as a structural requirement. Before concluding that 2 %%EOF markers represent an edit, check the first 1024 bytes for the /Linearized key.
