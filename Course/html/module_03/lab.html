Scenario

You have received a copy of an employment contract. The subject claims the salary was always $95,000 and the start date was always 7 April 2025. Your task is to use incremental update analysis to determine the original values and establish when and how they were changed.

ℹ️
Before You Begin

Open a terminal in the folder containing lab03_incremental.pdf. You will be creating a new file (lab03_v1.pdf) during this lab. Keep notes with space for: EOF count, byte offsets of each EOF, V1 MD5, Producer for each version, and the original salary and start date.

🔬 Exercise 1 — Count %%EOF Markers and Find Their Byte Offsets

The number of %%EOF markers tells you how many save operations the file has undergone. Run both commands: the first gives you the count, the second gives you the exact byte offset of each one — you will need those offsets in Exercise 2.

🪟 Windows
🐧 Linux / macOS
PowerShell — count and locate %%EOF markers
# Count total EOF markers:
python -c "d=open('lab03_incremental.pdf','rb').read(); print(d.count(b'%%EOF'),'%%EOF markers')"

# Get the byte offset of each (you need these for Exercise 2):
python -c "
d=open('lab03_incremental.pdf','rb').read()
pos=0; i=1
while True:
    idx=d.find(b'%%EOF',pos)
    if idx==-1: break
    print(f'Version {i} EOF at byte {idx}')
    i+=1; pos=idx+5
"
Bash — count and locate %%EOF markers
# Count total EOF markers:
grep -c '%%EOF' lab03_incremental.pdf

# Get byte offsets:
python3 -c "
d=open('lab03_incremental.pdf','rb').read()
pos=0; i=1
while True:
    idx=d.find(b'%%EOF',pos)
    if idx==-1: break
    print(f'Version {i} EOF at byte {idx}')
    i+=1; pos=idx+5
"
✅
What to record

Write these down in your notes before moving on:

  • Total %%EOF count (answers Q1 — number of incremental updates = count minus 1)
  • Version 1 EOF byte offset: _____ (you will use this in Exercise 2)
  • Version 2 EOF byte offset: _____
  • Version 3 EOF byte offset: _____

🔬 Exercise 2 — Extract Version 1 and Verify Its Contents

Copy all bytes from offset 0 up to and including the first %%EOF to create a standalone file representing the document as it existed before any edits. Open it in a PDF viewer to see the original content — this is the evidence that contradicts the subject's claim.

🪟 Windows
🐧 Linux / macOS
PowerShell — extract Version 1
# Extract Version 1:
python -c "
d=open('lab03_incremental.pdf','rb').read()
eof1=d.find(b'%%EOF')+5  # +5 to include the %%EOF bytes themselves
open('lab03_v1.pdf','wb').write(d[:eof1])
print(f'Extracted {eof1} bytes to lab03_v1.pdf')
"

# Verify the extracted file's integrity:
Get-FileHash -Algorithm MD5 lab03_v1.pdf
# Expected: 056b9bd1b4368afd95cf01dd83ceccde

# Open it in your PDF viewer to see the original values:
Invoke-Item lab03_v1.pdf
Bash — extract Version 1
# Extract Version 1:
python3 -c "
d=open('lab03_incremental.pdf','rb').read()
eof1=d.find(b'%%EOF')+5
open('lab03_v1.pdf','wb').write(d[:eof1])
print(f'Extracted {eof1} bytes to lab03_v1.pdf')
"

# Verify:
md5sum lab03_v1.pdf
# Expected: 056b9bd1b4368afd95cf01dd83ceccde

# Open to view original content:
xdg-open lab03_v1.pdf  # Linux
open lab03_v1.pdf      # macOS

What to record

  • lab03_v1.pdf MD5 matches expected value: 056b9bd1b4368afd95cf01dd83ceccde
  • Original salary as shown in lab03_v1.pdf (answers Q2)

🔬 Exercise 3 — Inspect the Modification Annotations

The changes were made by adding FreeText annotations on top of the original text. Use peepdf to find and read them. Each annotation has a /CreationDate that tells you when the edit was made — a timestamp that is separate from the document dates.

🪟 Windows
🐧 Linux / macOS
PowerShell — find and read annotations
peepdf -i lab03_incremental.pdf

# Step 1: list all annotation objects
pdf> search /Annot
# Note the object numbers shown

# Step 2: read each annotation object
pdf> object FIRST_ANNOT_OBJ_NUM
# In the output, look for and record:
#   /Subtype    <- the type of annotation (FreeText, etc.)
#   /Rect       <- the position on the page [x1 y1 x2 y2]
#   /Contents   <- the replacement text the annotation displays
#   /CreationDate <- when this annotation was added
#   /MK /BG     <- background colour ([1 1 1] = opaque white)

pdf> object SECOND_ANNOT_OBJ_NUM
# Repeat for each annotation found
pdf> exit
Bash — find and read annotations
peepdf -i lab03_incremental.pdf
pdf> search /Annot
# Note all annotation object numbers

pdf> object FIRST_ANNOT_OBJ_NUM
# Record: /Subtype, /Contents, /CreationDate, /Rect

pdf> object SECOND_ANNOT_OBJ_NUM
pdf> exit

What to record

Write these down in your notes before moving on:

🔬 Exercise 4 — Compare Producer Fields Across Versions

The /Producer field in each version's trailer reveals which application wrote that version. A Producer change between versions tells you a different application opened and resaved the file. This answers Q4 in the knowledge check.

🪟 Windows
🐧 Linux / macOS
PowerShell — Producer comparison
# Version 1 Producer (from the file you extracted in Exercise 2):
peepdf -i lab03_v1.pdf
pdf> metadata
# Look for: /Producer
# Record the exact string
pdf> exit

# Current version (V3) Producer:
exiftool lab03_incremental.pdf | findstr Producer
# Compare the two values
Bash — Producer comparison
# Version 1 Producer:
peepdf -i lab03_v1.pdf
pdf> metadata
# Record /Producer value
pdf> exit

# Current (V3) Producer:
exiftool lab03_incremental.pdf | grep Producer
✅
What to record

Write these down in your notes before moving on:

  • Version 1 Producer: _____ (the original authoring application)
  • Version 3 Producer: _____ (the application that made the edits)
  • These two values answer Q4 of the knowledge check

What the evidence shows

Version 1 (Producer: Microsoft Word 2019) is the original contract, created legitimately in Word. Versions 2 and 3 (Producer: Adobe Acrobat Reader DC 23.0) show that someone subsequently opened the file in Acrobat Reader and used the Fill & Sign annotation tool to overlay new values on the salary and start date fields. The original values — $85,000 and 3 March 2025 — are preserved intact in the bytes of Version 1, still present in the current file at byte offsets 0 through 1143.

📝 Knowledge Check Preparation

Q1: A PDF file contains 3 %%EOF markers. How many incremental updates does this indicate?
2 incremental updates. Number of updates = %%EOF count minus 1. The first %%EOF ends the original creation; each subsequent %%EOF ends one incremental save. Three %%EOF markers = original + 2 saves.
Q2: When extracting Version 1, what bytes do you copy?
All bytes from offset 0 up to and including the first %%EOF. In Python: d[:d.find(b'%%EOF')+5]. The +5 includes all five bytes of the %%EOF string itself. Copying less than this (stopping before %%EOF) produces an incomplete file that some viewers will reject.
Q3: What does the /Prev entry in an incremental update trailer do?
It stores the byte offset of the previous version's xref table. This creates a chain of /Prev pointers that allows any PDF reader — and any forensic examiner — to walk backwards through every version of the document. To read V2's trailer, jump to the V3 xref table and read its /Prev entry; that gives you the offset of the V2 xref, whose /Prev gives you V1's xref.
Q4: V1 Producer is 'Microsoft Word 2019' and V2 Producer is 'Adobe Acrobat Reader DC 23.0'. What does this indicate?
The document was originally created in Microsoft Word (V1). Someone subsequently opened the file in Adobe Acrobat Reader and saved it, producing V2 (and V3). Adobe Acrobat Reader's Fill & Sign feature was used to add the annotation overlays that changed the salary and start date values.
